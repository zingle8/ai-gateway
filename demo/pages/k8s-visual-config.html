K8s 名词「人话」速查
给不熟悉 K8s 的同学：这些概念各自解决什么问题
Pod 最小单位
运行容器的「盒子」。一个 Pod 里通常只放一个主容器，K8s 调度、重启都以 Pod 为单位。
Deployment 部署
声明「跑几个 Pod、用什么镜像」，负责滚动更新、回滚和自愈（Pod 挂了自动补）。
Service 稳定入口
Pod 的 IP 会变，Service 提供固定虚拟 IP 与 DNS 名，并把请求负载均衡到后端 Pod。
Ingress 对外域名
把域名和路径映射到 Service，顺带处理 HTTPS 证书，相当于集群的统一大门。
requests / limits 资源配额
requests 是「至少要给我这么多」用于调度；limits 是「最多只能用这么多」。CPU 超了限速，内存超了重启。
探针 健康检查
liveness 失败重启容器，readiness 失败暂时不接流量。启动慢的应用一定要调大首次探测延迟。
HPA 弹性伸缩
按 CPU / 内存等指标自动增减 Pod 数量，扩容激进、缩容保守，避免抖动。
ConfigMap / Secret 配置
把配置和镜像解耦，改配置不用重新打包镜像。Secret 专门放密码类数据。
优雅下线 零中断
Pod 销毁前先让注册中心摘流（preStop 等待），处理完存量请求再退出，避免 502。
PDB 驱逐保护
节点排空或升级时，保证至少还有 N 个 Pod 可用，防止「一起被赶走」导致服务全挂。
两种用法，任选其一
