约定式自动生成（接入即得，无需手配）
系统接入（手动或自动）时，网关按命名约定创建空间与配置项骨架；值来自项目等级默认模板，直接用就能跑
默认生成 · 可覆盖
对象 生成规则（约定） 示例（appcode=trade-order, P1, 华东） 说明
命名空间 gw-{region}-{appcode} gw-cn-east-1-trade-order 按「地域 + 应用」隔离；已存在则复用，不重建
Group GATEWAY_{LEVEL} GATEWAY_P1 按等级分组，便于批量下发与权限控制
路由配置 {appcode}-route.yaml trade-order-route.yaml 默认路由 /api/order/** → lb://order-service
鉴权配置 {appcode}-auth.yaml trade-order-auth.yaml 默认 AK-SK（P0 追加 mTLS）
限流配置 {appcode}-limit.yaml trade-order-limit.yaml P1 默认 400 QPS + 突发 600
插件配置 {appcode}-filter.yaml trade-order-filter.yaml 默认开启 TraceId / 限流 / 审计，其余按需
生成时做了什么
# 接入时自动执行（幂等） 1. 创建/复用命名空间 gw-cn-east-1-trade-order 2. 创建 Group GATEWAY_P1 3. 写入 4 个 dataId 骨架（值取自 P1 默认模板） 4. 绑定监听：网关实例长轮询，1 秒内热更新 5. 记录版本快照 v1，作为回滚基线
骨架文件内容（限流示例）
# trade-order-limit.yaml（自动生成，默认即可用） limit: qps: 400 # P1 默认 burst: 600 strategy: token-bucket dimension: [appcode, routeId]
怎么覆盖（两种方式）
# A. 应用侧声明（bootstrap.yml） gateway: nacos: namespace: gw-cn-east-1-trade-order # 可改 group: GATEWAY_P1 # 可改 data-id-prefix: trade-order # 可改 # 不写 → 全部按约定生成（推荐） # B. 控制台手动改 → 该 dataId 标记「手动锁定」
命名冲突空间已存在则复用，绝不覆盖已有配置
手动锁定控制台改过的 dataId，自动生成跳过
前缀重复dataId 前缀冲突时报错并提示，不静默覆盖
重新托管需控制台点「恢复自动托管」
删除保护自动流程永不删除 dataId，只增不改
