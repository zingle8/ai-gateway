方式② · SDK Starter 自动注册
应用启动即注册，无需在控制台点任何按钮
零配置起步
1. 引入依赖
<dependency> <groupId>com.zimo.gateway</groupId> <artifactId>jv-api-gateway-client-starter</artifactId> <version>1.6.2</version> </dependency>
2. 最小配置（只填 4 项，其余全部默认）
gateway: client: enabled: true # 默认 true，可关闭 register-url: http://gw-console:8080 # 默认内置，可不填 bootstrap-token: ${GATEWAY_BOOTSTRAP_TOKEN} # 平台颁发，环境变量注入 appcode: trade-order # 必填 · 我的代号 appname: 交易订单系统 service-name: order-service # 必填 · 注册中心服务名 region: cn-east-1 # 必填 · 华东 level: P1 # 必填 · 决定默认模板 protocol: HTTP # 默认 HTTP（可 gRPC / WS） # 以下全部走默认模板，不写即可： # timeout / retry / limit-qps / circuit-breaker / 熔断阈值 # auth-mode（默认 AK-SK）/ 脱敏规则 / 日志采样率
3. 启动日志（12 秒内完成接入）
[gateway-client] 读取配置：appcode=trade-order, service=order-service, region=cn-east-1, level=P1 [gateway-client] 注册中 → http://gw-console:8080/gateway/v1/systems:register [gateway-client] ✔ 已接入 appid=10086 appcode=trade-order（幂等命中，未重复创建） [gateway-client] ✔ 下发默认配置：qps=400 timeout=3s retry=1 breaker=50% [gateway-client] ✔ 默认路由已生成：order-api → lb://order-service /api/order/** [gateway-client] ✔ Nacos 实例注册成功（10.24.6.11:8080），健康检查通过，已上线
自动接入时序
注册是幂等的：重复启动、扩缩容、重启都不会重复创建
应用启动，Starter 读取 bootstrap.yml
必填项缺失 → 启动失败并明确报错（fail-fast，避免半接入状态）
携带 bootstrap token 调用注册 API
token 由平台颁发（有效期 90 天、可吊销），无 token 一律拒绝
网关按 appcode + service-name 幂等创建系统
已存在则复用 appid；不会覆盖「手动锁定」字段
按项目等级下发默认配置模板
P1 → 400 QPS / 超时 3s / 重试 1 次 / 熔断 50% / AK-SK 鉴权
生成默认路由（/api/{服务名}/**）
默认轮询 LB + 健康检查；后续可在控制台改，改后自动锁定
按约定创建 Nacos 空间与配置项骨架
gw-cn-east-1-trade-order / GATEWAY_P1 + route / auth / limit / filter 四个 dataId（详见 ② Nacos 配置空间）
实例注册到 Nacos → 健康检查通过 → 上线
实例下线 / 进程退出 → 主动注销，30 秒摘除流量
失败与异常处理
注册失败退避重试 5 次（1s→30s），仍失败则启动失败
控制台不可达本地缓存上次配置继续启动（降级可用）
token 失效拒绝注册并告警，需平台重新颁发
重复启动幂等，不重复创建系统与路由
进程退出优雅注销，实例摘除、路由保留
默认配置模板（按项目等级）· 约定大于配置
不写就有：接入即拿到一套经过验证的默认值；要改再覆盖，改哪算哪

关键规则
字段级锁定控制台改过的字段标记 locked，自动接入跳过
未锁定字段应用重启时按配置重新对齐（可收敛漂移）
删除保护自动接入只增不改已锁定项，永不删除路由
冲突提示配置与控制台冲突时告警，不静默覆盖
解锁方式控制台手动「恢复自动托管」才会重新托管

安全与治理
注册凭证bootstrap token，一系统一枚，有效期 90 天，支持吊销与轮换
准入校验appcode 命名规范、服务名唯一性、地域合法性、等级权限校验
配额保护自动接入受项目等级配额上限约束，防止随意占资源
审计留痕自动接入同样进入变更审计，可追溯是谁、哪台机器、何时注册
手动优先控制台已配置的系统，自动注册只做「对齐未锁定字段」
Java 接入 · 三步
Spring Boot 项目加依赖 + 填 4 项配置，启动即接入
已支持
1. 引入依赖
<dependency> <groupId>com.zimo.gateway</groupId> <artifactId>jv-api-gateway-client-starter</artifactId> <version>1.0.0</version> </dependency>
2. 填写配置
zimo: gateway: client: server-addr: http://127.0.0.1:28080/api # 平台统一入口 app-id: app-order app-name: 订单中心 service-name: order-service port: 8000
3. 启动应用
启动完成后自动注册，每 30 秒心跳，退出时主动注销；请求经 Servlet Filter 采集， 内存队列批量上报。不需要写任何代码。
Python 接入 · 三步
零第三方依赖（标准库实现），Flask / FastAPI / 脚本均支持
已支持
1. 引入 SDK
# 无需安装，把 sdk/python 加进 PYTHONPATH 即可 export PYTHONPATH=/path/to/ai-gateway/sdk/python:$PYTHONPATH
2. 接入（以 Flask 为例）
from jv_gateway import GatewayClient from jv_gateway.wsgi import WSGITraceMiddleware client = GatewayClient( server_addr="http://127.0.0.1:28080/api", app_id="app-order", app_name="订单中心", service_name="order-service", port=8000, ) client.start() # 关键一行：自动采集请求与响应 app.wsgi_app = WSGITraceMiddleware(app.wsgi_app, client)
3. FastAPI 只需换中间件
from jv_gateway.asgi import ASGITraceMiddleware app.add_middleware(ASGITraceMiddleware, client=client)
Java · 引用 jar 包接入（不接私服）
业务方拿不到源码、或没有 Maven 私服时：把 SDK 打包分发，装进本地仓库后照常声明依赖
离线分发
1. 生成分发包
# 网关平台项目根目录执行 bash scripts/build-sdk-jar.sh # 产出 dist/sdk-jar/ # install.sh 一条命令装好 # lib/api-gateway-1.0.0.pom parent，解析依赖版本必需 # lib/jv-api-gateway-client-common.jar + .pom # lib/jv-api-gateway-client-starter.jar + .pom
2. 业务机器上安装
# 把 dist/sdk-jar 整个拷过去，然后： cd dist/sdk-jar && ./install.sh # 等价手工命令（顺序不能反） mvn install:install-file -Dfile=api-gateway-1.0.0.pom \ -DgroupId=com.zimo.gateway -DartifactId=api-gateway \ -Dversion=1.0.0 -Dpackaging=pom
3. 声明依赖（与 Maven 方式一致）
<dependency> <groupId>com.zimo.gateway</groupId> <artifactId>jv-api-gateway-client-starter</artifactId> <version>1.0.0</version> </dependency>
三个文件缺一不可
  • parent 必须装：starter 的 pom 继承 com.zimo.gateway:api-gateway:1.0.0，缺它解析不到依赖版本，直接报 Could not find artifact
  • 要带 -DpomFile：只给 jar 会生成空 pom，传递依赖 jv-api-gateway-client-common 丢失，启动报 NoClassDefFoundError
  • 安装顺序：parent → client-common → client-starter，install.sh 已按此顺序
  • web 依赖：starter 内 spring-boot-starter-web 为 optional，Web 项目本身自备
使用说明 · 接入后常见问题
接入不生效时，按这几条逐项对，基本都能定位
排障手册
server-addr 填错必须指向平台统一入口（如 http://127.0.0.1:28080/api），不是某个微服务端口；SDK 会自行拼接 /discovery、/trace 前缀，填成单服务端口必然一半请求 404
服务发现看不到检查 registry.enabled 是否为 true、网络是否可达、service-name 是否被别的实例覆盖
日志追踪没数据检查 trace.enabled、sample-rate 是否为 0、路径是否命中 exclude-paths；Python 需确认中间件真的挂到了应用上（Flask 赋给 wsgi_app，FastAPI 用 add_middleware）
上报失败会拖累业务吗不会。日志进内存队列立即返回，队列满直接丢弃，上报异常只记日志不重试、不抛出
多实例部署以 service-name 为唯一键幂等更新，多实例共享一条服务记录，不会重复创建
只想注册或只想采集两个开关独立：registry.enabled 控制注册 + 心跳，trace.enabled 控制采集上报
报文体太大调小 max-body-size（默认 8KB 截断）、降低 sample-rate，或把健康检查路径加进 exclude-paths
怎么算接入成功「服务发现」出现该服务名，「日志追踪」出现对应调用记录，错误类型按状态码自动归类（如 404 → 路由失败）
